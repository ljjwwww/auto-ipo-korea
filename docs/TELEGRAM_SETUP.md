# Telegram 개인 알림 연결

## 사용자가 해야 하는 작업

1. 텔레그램 공식 **@BotFather**에 `/newbot`을 보내 봇을 만듭니다. 이름/username은 원하는 값으로 정합니다.
2. 발급 토큰을 **채팅·Git·CLI 인수에 붙이지 않습니다.** 아래 명령을 본인 WSL 터미널에서 실행합니다.

```bash
cd /home/ljjw/projects/ipo-monitor
uv run ipo-monitor telegram setup
```

숨김 프롬프트에 토큰을 두 번 입력합니다. 화면에 나온 일회성 `/start ...` 명령을 **방금 만든 봇의 개인 대화**에 보내고 터미널에서 Enter를 누릅니다. 이 일회성 문자열과 일치하는 개인 대화 하나만 연결합니다. 그룹·다른 사람의 이전 메시지를 자동 선택하지 않습니다. 기존 webhook은 자동 삭제하지 않으며 충돌하면 별도 새 봇을 사용하거나 본인이 기존 연결을 확인해야 합니다.

3. 상태와 전송 전 미리보기를 확인합니다.

```bash
uv run ipo-monitor telegram status
uv run ipo-monitor telegram preview
```

4. 실제 개인 알림을 활성화하고 현재 요약을 한 번 보냅니다.

```bash
uv run ipo-monitor telegram enable
uv run ipo-monitor telegram send --allow-send
```

`enable`은 명시적인 지속 전송 동의입니다. 기존 Windows **매일 19:00 KST** 작업은 같은 `daily` 명령을 사용하므로 다음 실행부터 수집·분석 뒤 Telegram도 실행합니다. 등록 작업 인수에 토큰을 넣거나 새로 예약할 필요가 없습니다. 별도의 AI 요청은 `telegram send`에서 발생하지 않습니다. AI 대기 해소는 `daily --allow-api`가 담당합니다.

끄기:

```bash
uv run ipo-monitor telegram disable
```

## 저장과 전송 계약

- 키/대화 ID: 로컬 `data/secrets/telegram.json`, 권한600, 부모 디렉터리700. **평문**이므로 계정·백업을 보호해야 합니다. Git 제외. 키 값·대화 ID는 상태 출력/로그에서 숨깁니다.
- 공개 `config/telegram.toml`에는 활성화 여부와 경로만 있습니다. 초기 상태는 `enabled = false`입니다. 준비만으로 전송하지 않습니다.
- 현재 입력·정책과 일치하는 실제 Ollama 판단만 요약합니다. 고정 응답 실험/오래된 판단/과거 전이 전체를 전송하지 않습니다. 판단 불가/미처리·수집 문제·사이트 별점은 숨기지 않습니다.
- 처음 켜면 현재 종목 요약을 보냅니다. 이후 동일 요약은 중복 억제하고 상태가 바뀌면 다시 보냅니다. 요약이 길면 안전한 길이로 나누어 평문으로 전송합니다.
- 전송 원장은 `data/telegram-delivery.sqlite3`이며 본문 preview outbox와 별개입니다. 전송 전 상태를 영속 저장합니다. 타임아웃·연결 중단·확인 불가능한 응답은 **unknown**으로 남기고 같은 요약을 무조건 재전송하지 않습니다. 이후 자료가 달라진 새 요약에는 기존 종목이 다시 포함될 수 있습니다. 원격 서버 도달 여부를 알 수 없으므로 exactly-once 보장은 없습니다.
- 별점은 평가 신호이고 작성자의 실제 청약 실행 선언은 아닙니다. 점수는 미검증 초기 정책입니다. 주문은 실행하지 않습니다.

## 일일 AI 한도

사용자 요청에 따라 `config/daily.toml`의 `max_calls_per_day = 600`입니다. Ollama 모델 인스턴스와 설정 검증도 600회를 허용합니다. 같은 한국 날짜의 이전 일일 요청도 합산하며 실패 요청을 환급하지 않습니다. 수동 `assess`/별도 실험 호출은 이 원장 밖입니다. 600은 **최대 횟수이지 자동으로 600회 호출한다는 뜻이 아닙니다.** 20분 실행 예산 후 새 AI 요청을 보류하고 다음 실행으로 넘기며, 성공 캐시를 재사용합니다. Windows 작업의 30분 제한 전에 정상 저장할 여유를 둡니다.

## 현재 분석 범위의 한계

- 유튜브는 최신3개 영상이며 특정 종목의 과거 관련 영상 전체 검색은 구현하지 않았습니다.
- 공통 일일 분석은 블로그 RSS를 사용합니다. 기존 별도 pipeline의 본문 재분석 기능이 일일 다중 출처 흐름에 자동 연결된 것은 아닙니다.
- 과거 날짜 가정은 당시 자료가 보존된 백테스트와 다릅니다. 로컬 별도 예시를 일일 운영 결과로 혼동하지 않습니다.
- 연결 전 검증은 mock 테스트/미리보기이며, 토큰·대화 연결 후 실수신을 확인해야 실제 전달 검증 완료입니다.

공식 문서: [봇 생성](https://core.telegram.org/bots/features#creating-a-new-bot), [getUpdates](https://core.telegram.org/bots/api#getupdates), [sendMessage](https://core.telegram.org/bots/api#sendmessage), [전송 한도](https://core.telegram.org/bots/faq#my-bot-is-hitting-limits-how-do-i-avoid-this).
