# 3개 출처 종합 판단·알림 계획

**2026-11-15 사용자 확정. 수집·변경 이력·후보 조회 묶음은 이후 별도 승인으로 구현했다. 종합 판단·알림 등 전체 계획이 완료된 것은 아니다. 최신 구현/명령은 [사용법](MULTI_SOURCE_USAGE.md) 참조.**

## 1. 확정한 방향

```text
네이버 블로그(팽) ─┐
유튜브 영상(기릿) ─┼→ 출처별 데이터 축적 → 종목별 연결·변경 추적
유튜버 사이트(기릿) ┘                     ↓
                              가중치를 반영한 종합 판단
                                         ↓
                            Telegram 또는 Slack 개인 알림
                                         ↓
                                 사용자가 청약·매도
```

- 목적은 단일 출처의 명시적 참여 선언만 복사하는 것이 아니다. 여러 출처의 평가·발언·별점·일정·추가 데이터 등을 쌓아 종합 판단하고 알린다.
- 별점, 추천 표현, 조건부 발언, 판단 보류, 종목별 후속 정보를 **판단 재료로 보존**한다. AI가 자체 정책으로 특정 신호를 판단에서 배제하거나 사용 불가로 결정하지 않는다.
- 원문의 의미와 시스템 종합 판단은 구분해 설명한다. 예를 들어 원문이 별점이면 별점으로 보존하면서, 사용자가 정할 가중치/규칙에 따라 종합 판단에 활용할 수 있다.
- 출처별 의견과 종합 판단이 다를 수 있다. 알림은 최종 판단과 함께 근거·출처·기준 시점을 추적할 수 있어야 한다.
- 이 단계의 청약·매도는 사용자 직접 실행. 자동주문과 별개다.
- 런타임 AI 제공자 연동에 앞서 출처를 확장하는 방향으로 우선순위를 변경했다. 첫 수집·이력·후보 조회 묶음은 이후 개발 요청으로 승인받아 구현했다. 종합 판단·알림은 아직 후속 범위다.

## 2. 고정한 세 출처

| 출처 | 주소·식별자 | 모을 데이터의 계획 |
| --- | --- | --- |
| 네이버 블로그 — 팽 | https://blog.naver.com/hycj1025 / RSS https://rss.blog.naver.com/hycj1025.xml | 제목·시각·링크·RSS 설명, 필요 시 공개 본문, 종목별 의견·조건·근거 |
| 유튜브 — 기릿 | https://www.youtube.com/@%EC%BD%94%EC%8A%A4%EB%8B%A5 / channel ID `UCw8pcmyPWGSik7bjJpeINlA` | 새 영상, 제목·설명·시각, 한국어 자막, 타임스탬프별 종목·평가·참여 발언·후속 판단 예고 |
| 유튜버 사이트 — 기릿 | https://letsgetitstock.com/ipo | 달력·종목·별점/표시 원문·일정·수요예측 등 공개된 항목과 변경 이력 |

기릿 영상과 사이트는 같은 작성자의 두 채널임을 provenance에 남긴다. 이것은 임의 제외나 감점 규칙이 아니다. 같은 내용의 중복 집계 방법과 가중치는 사용자와 정한다.

## 3. 판단 보류와 후속 관찰

사용자가 제시한 사례: 에스에프씨·유캐스트는 영상에서 기관 참여 등 추가 데이터가 모이면 판단을 알려주겠다고 했으므로, 그 시점의 영상/사이트 업데이트를 함께 본다.

- 데이터가 아직 없다는 것과 부정적 평가/미참여를 구별해 저장한다.
- 종목을 버리거나 감시를 종료하지 않고 **후속 데이터 대기** 상태로 이어서 추적한다.
- 달력에 종목이 있는지와 별점이 있는지는 별도 상태다. 별점 없음도 원문 그대로 보존하고 후속 변화를 관찰한다.
- 새 영상, 기존 페이지 평가/수치 변화, 후속 블로그 글이 들어오면 이전 자료와 연결해 판단을 갱신하는 흐름을 계획한다.
- 영상 제목의 권유, 발언자의 실제 참여 진술, 사이트 매력도, 시스템 종합 판단은 다른 필드로 보존하되 모두 종합 판단의 후보 신호다.

## 4. 판단·가중치 — 아직 정하지 않은 것

세 출처를 쓰는 방향은 확정됐지만 다음 수치/정책은 아직 구현하거나 확정하지 않았다. 이후 사용자 지시는 추가 인터뷰 없이 권장안으로 진행하는 것이다. 이번 수집 묶음에는 점수/판단 기준을 넣지 않았고, 후속 작업에서 권장안과 적용 근거를 명시해 진행한다. 유료 호출·외부 전송 승인 범위를 임의 확대하지 않는다.

- 출처별/신호별 가중치와 산식 또는 AI 판단과 규칙의 분담.
- 별점/❌/평가 부재를 점수에 반영하는 방법과 관심·참여 후보 임계값.
- 같은 작성자의 영상·사이트가 중복되거나 서로 다를 때 반영 방법.
- 종목/공모 건 연결 기준, 최신성·신뢰도·의견 변화 처리.
- 판단 보류 종목의 재조사 주기, 청약 마감 임박 시 처리, 누락/수집 실패 알림.
- Telegram vs Slack, N일 전 기준과 새 판단/변경 알림 시점·빈도.
- 런타임 AI 제공자·모델·호출 범위/비용 한도. Ollama Cloud는 검토 중이며 미연동이다.

기존 참여/조건부/미참여/판단 불가 분류는 **개별 출처의 의견 추출** 계약이다. 이를 그대로 종합 판단 공식이나 단일 출처 필수 게이트로 고정하지 않는다.

## 5. 역할 분리 (계획)

| 계층 | 역할 |
| --- | --- |
| Non-AI 수집·저장 | 출처 감시, RSS/페이지/자막 확보, 시간·원문 신호·해시·변경 이력 보존 |
| AI 의미 해석 | 발언/글의 종목·의견·조건·근거·후속 판단 예고 해석 |
| 종합 판단 | 사용자가 정할 가중치·규칙 및 AI 역할에 따라 출처들을 함께 평가 |
| Non-AI 알림 | 일정·중복 방지·전송 상태 관리, 근거/링크를 붙여 개인 채널에 전달 |
| 사용자 | 최종 청약·매도 실행, 중요한 제품/판단 정책 결정 |

정형 별점/일정은 코드로 읽고, 문맥 해석이 필요할 때 AI를 호출하는 비용 절감 설계는 검토 가능하다. 사이트만 사용하거나 자막을 생략하는 정책을 확정한 것은 아니다.

## 6. 현재 확인된 것과 구현 상태

- 블로그 수집/본문 확인과 샘플 의미분석은 기존 코드에 있다. 실제 유료 AI 호출은 0회다.
- 지정한 기릿 영상 2건에서 `yt-dlp`로 한국어 원어 자동자막(`ko-orig`)만 수집했다. 영상/음원은 다운로드하지 않았다. 자막을 타임스탬프 텍스트로 정리한 로컬 실험이며 정식 소스 어댑터는 미구현이다.
  - https://www.youtube.com/watch?v=7uhTGAHdoCI : 약 3,721자, 정리 구간207개.
  - https://www.youtube.com/watch?v=6Fca1pqfQYo : 약 2,628자, 정리 구간144개.
- 사이트는 로그인 없이 HTTP200으로 읽었고 HTML에서 청약 달력 라벨26개를 시험 추출했다. 별점은 사이트 소개에서 매력도로 설명한다. 이는 수집 가능성 확인이며 정식 수집/판단 연동 완료가 아니다.
- 로컬 수집 파일은 `data/youtube-check/` 등 Git 제외 경로에 있다. 원문/자막을 소스 저장소에 추가하지 않는다.
- `config/sources.toml`과 실행 코드는 **아직 블로그 한 곳만 정식 지원**한다.
- 유튜브/사이트 정식 수집, 다중 출처 연결·가중 판단, Telegram/Slack, 예약 실행은 미구현이다.
- 수집 안정성·접근 조건·이용약관 관련 사실은 구현 시 확인·보고한다. 이들을 이유로 AI가 사용자 확정 출처나 판단 정책을 임의로 변경하지 않는다. 별도의 권한/비용 문제가 발생하면 사용자에게 전달한다.

## 7. 요청 이력과 현재 구현 경계

초안 당시에는 문서 반영만 요청했으므로 개발하지 않았다. 이후 사용자가 첫 권장 개발 묶음 착수를 승인했고, 인터뷰에서 `explicit_alias_candidates`를 선택한 뒤 추가 인터뷰 없이 권장안으로 진행하도록 변경했다.

완료: 세 출처 설정/수집, 자막 정리, 사이트 달력/표 원문 관찰, 불변 변경 이력, 종목명·명시적 별칭 기반 후보 조회, 오프라인/실제 반복 검증. 초기 출처별 수집 시험만 했다는 위 6절 설명은 초기 기록이다.

미완료: 세 출처의 AI 분석 연결, 가중 종합 판단, Telegram/Slack, 예약 실행·주문. 실제 AI 실호출 승인 범위를 임의 확대하지 않는다. [사용법과 검증 결과](MULTI_SOURCE_USAGE.md)를 현재 구현 상태의 기준으로 읽는다.

## 8. 후속 1~3번 구현 승인 및 완료

사용자는 공통 분석 입력·초기 가중 판단 구조·고정 응답 전체 흐름 검증을 승인하고 완료 후 Git 버전 게시를 요청했다. 0.2.0은 이 구조를 fixture 전용으로 구현한다. 실제 AI/전송/운영 정확도는 미검증이다. [상세 사용법](ASSESSMENT_USAGE.md)을 현재 기준으로 읽는다. 기존 미구현 목록 중 가중 판단은 이제 실험 구조로 구현됐지만 실사용 검증은 남아 있다.
