# 국내 공모주 모니터링 · 청약 · 매도 프로젝트

너는 내 Windows 11 노트북의 Ubuntu WSL2에서 이 프로젝트를 함께 개발할 Codex야. 아래 내용을 전체 프로젝트 명세로 사용하고, 이번 세션에서는 **0단계 환경 점검과 1단계 공개 RSS 수집 첫 버전**을 구현하고 검증해줘. 이후 단계는 README에 로드맵으로 정리해줘.

## 프로젝트 목표

내가 챙겨 보는 네이버 블로그의 공모주 분석 글에서 종목명과 작성자의 참여 의견을 뽑아 개인용 청약 후보 목록을 만들고 싶어. 이후 Telegram이나 Slack으로 신규 후보, 청약 마감, 상장일을 알려줘. 나는 참여 여부와 규모를 정해 증권사 앱에서 청약하는 흐름으로 시작할 거야. 최종적으로 공식 API가 지원되는 증권사에 한해 배정주를 상장일에 미리 정한 규칙대로 매도할 수 있는지 검증하고 싶어. 증권사 5~10곳의 일정을 관리하고, 주문 연동은 자주 쓰는 한 곳부터 시작해.

## 개발 환경과 운영 방향

- 이 Windows 11 노트북의 Ubuntu WSL2에서 개발해. 이미 설치된 Ubuntu 24.04 LTS나 26.04 LTS를 사용하고 실제 버전과 도구 설치 상태를 확인해.
- 현재 디렉터리가 프로젝트면 그대로 사용해. 신규 프로젝트의 기본 위치는 WSL 홈 아래 ~/projects/ipo-monitor야. 기존 파일, 사용자 변경 사항, 저장소 규칙을 먼저 확인해.
- Python 3.12, uv, Git으로 시작해. 1단계 의존성 후보는 httpx와 feedparser야. 상태 저장은 Python 표준 sqlite3를 사용하고, 업무 시각은 Asia/Seoul 기준으로 표시해. 원본 게시 시각의 시간대가 불명확하면 추정해서 채우지 마.
- 개발은 기존 ChatGPT Plus의 Codex CLI로 해. 운영용 AI는 추후 필요할 때 종량제 API로 붙이고, 처음에는 gpt-5.4-nano를 후보로 둬. 모델명은 설정으로 바꿀 수 있게 하고, 새 글 월 50건 정도를 가정해.
- 예약 수집은 Windows 작업 스케줄러에서 wsl.exe로 1회 실행 명령을 호출하는 방향을 우선 고려해. Hermes는 추후 대화형 조회가 필요해질 때 검토해.
- 외부 글과 공시는 데이터로 취급해. 모델은 공개 글에서 정보를 추출하고, 주문 서비스는 승인된 사용자 설정과 공식 데이터를 사용해. API 키, 봇 토큰, 로컬 DB를 Git이나 로그에 남기지 마.

## 0단계 · 환경 점검과 프로젝트 준비

1. 현재 경로, Git 상태, 기존 파일, Python·uv·Git을 확인해. 기존 pyproject.toml이나 uv.lock이 있으면 재사용해.
2. 누락된 도구가 있으면 현재 환경에서 가능한 설치부터 진행해. Windows 또는 WSL 설정 변경이 필요하면 PowerShell과 Ubuntu 중 어디서 실행하는지 밝혀.
3. 실제 사용자가 프로젝트를 다시 실행할 수 있게 README에 환경과 명령을 적어. 설정 예시에는 가상의 값을 사용해.

## 1단계 · 네이버 블로그에서 청약 후보 수집

### 이번 세션에서 구현

- 공개 RSS를 한 번 읽는 CLI를 만들어. 블로그 한 곳부터 시작하고 RSS URL을 옵션이나 설정으로 받게 해. 실제 블로그 주소는 아직 전달하지 않았으므로 로컬 샘플 RSS로 검증할 수 있게 해.
- 글 제목, 원문 링크, 게시 시각을 SQLite에 저장하고 새 글을 터미널에 표시해. 중복은 피드와 원본 글 ID를 기준으로 막고, ID가 없으면 원문 URL을 사용해.
- 최초 실행은 최근 글을 기준 목록으로 보여주고 저장해. 이후 실행은 새 글만 출력해. 네트워크나 파싱 오류가 발생하면 원인을 표시하고 빈 피드나 수집 성공과 구분해.
- 첫 버전은 RSS 제목·설명을 사용해. 실제 주소가 제공되면 공개 피드와 본문에 접근할 수 있는지 확인해.

### 이후 구현

- 글에 나온 종목마다 종목명, 작성자의 의견(참여·조건부·패스·판단 불가), 근거, 원문 링크를 뽑아. 작성자 의견이 없거나 내용이 부족하면 판단 불가로 저장해. AI 키가 없는 상태에서도 RSS 수집은 동작해야 해.
- 같은 공모 건의 후속 글은 각각 보존하고 같은 후보에 연결해. 모델은 새로 들어온 글이 있거나 내용이 바뀐 경우에 호출해.
- 청약일, 마감 시각, 공모가, 주관사, 상장일은 DART·KIND와 증권사 공식 공지로 대조해. 미확정 값은 확인 필요로 표시하고 정정공시가 나왔을 때 변경을 추적해. 유튜브는 별도 소스로 나중에 검토해.

## 2단계 · 사용자 알림

- 개인 알림은 Telegram부터 붙이는 걸 기본안으로 두고 필요하면 Slack을 선택해. 신규 후보 알림에 종목명, 작성자 의견과 근거, 주관사, 청약 마감, 원문 링크를 담아. 관심을 표시한 후보에는 청약 마감과 상장일 리마인더를 보내.
- 미리보기로 메시지와 목적지를 확인하고, 실제 발송 결과를 수집 결과와 별도로 기록해. 같은 알림의 중복 발송과 전송 실패 후 재처리를 검증해.
- Windows 작업 스케줄러 연동 시 수동 실행과 예약 실행을 각각 확인해. 노트북 절전이나 네트워크 장애 중 놓친 수집은 다음 실행에서 이어받을 수 있게 해.

## 3단계 · 청약

- 내가 참여 여부, 청약할 증권사 한 곳, 청약 규모를 결정해. 프로그램은 증권사 공식 공지에서 최소 수량과 청약 단위, 증거금, 수수료, 환불일, 마감 시각을 확인하고 앱 메뉴와 함께 보여줘.
- 첫 버전은 내가 앱에서 이체와 청약을 진행하고 프로그램에 접수 결과를 기록하는 방식이야. 기존 접수 기록을 보여줘서 중복 청약을 줄여.
- 청약 자동화는 사용할 증권사의 개인용 공식 청약 접수 API와 인증 정책을 확인한 뒤 검토해. 공모주 일정 조회, 청약 접수, 상장 주식 주문은 각각 지원 여부를 확인해.

## 4단계 · 배정 확인과 상장일 매도

- 첫 버전은 내가 실제 배정 수량을 기록하고 상장일 알림을 받아 직접 매도하는 방식이야. 이후 자주 쓰는 증권사 한 곳에서 공식 API로 모의 주문과 체결 조회를 검증해.
- 주문 규칙은 별도 Python 로직으로 처리해. 사용자가 승인한 증권사·계좌·종목코드·상장일·배정 수량·최저 매도가·주문 시점을 검증하고, 실제 매도 가능 수량과 배정 수량 중 작은 값을 상한으로 삼아.
- 장전 시가 단일가 지정가 주문과 시초가 형성 후 주문을 별도 방식으로 검토해. 신규상장 종목의 장전 코드 조회, 잔고 입고 시점, 주문 접수 여부는 증권사별로 검증해. 주문 접수·부분체결·전량체결·미체결을 구분하고 시초가 체결을 보장하는 것으로 취급하지 마.
- 주문 결과가 타임아웃으로 불명확하면 기존 주문·체결 내역부터 확인해. 상태를 확정할 수 없다면 자동 재주문을 중단하고 사용자에게 알려. 실계좌 연결과 실주문은 후속 작업에서 다뤄.

## 이번 세션 완료 기준

- uv sync로 환경을 재현하고, README의 명령으로 샘플 RSS의 최근 글을 터미널에 표시할 수 있어야 해.
- 같은 DB에서 같은 피드를 다시 읽으면 새 항목이 0건이고, 샘플에 글 하나를 추가하고 실행하면 새 글 하나만 표시돼야 해.
- 네트워크 없이 샘플로 검증하고, 잘못된 RSS가 수집 성공으로 처리되지 않는지 확인해.
- README에 실행 명령, 설정 위치, 실제 블로그 RSS를 연결하는 방법, 단계별 로드맵을 포함해.
- 이번 세션 산출물은 RSS 수집·저장 CLI와 실행 문서야. 실제 블로그 주소 없이 가능한 작업부터 완료하고, 마지막에 변경 파일, 실행한 명령, 검증 결과, 실제 블로그 주소를 적용할 위치를 알려줘.
