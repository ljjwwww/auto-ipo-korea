# 최신 확정 흐름: 월별 청약 목록 + 새 언급 이벤트

2026-11-17 사용자 결정. 이전 '전체 종목 종합 판단 요약을 변경 시 재전송' 방식은 운영에서 중단한다. `config/daily.toml`의 `workflow="mention_events"`가 실제 예약 실행 경로다.

## 동작

0. 기릿 사이트에서 **현재 월에 청약 기간이 걸쳐 있고 종료되지 않은 종목** 목록을 확보한다. 달력의 연도까지 명시된 청약 날짜를 우선 사용한다. 상장일만 있는 과거 종목·다음 달 종목·연도 미확인 표 항목은 활성 알림 대상에 넣지 않는다. 사이트의 현재 항목 목록과 과거 수집 이력을 구분한다.
1. 매일19:00 KST 블로그 RSS·유튜브 최신3개·기릿 사이트를 수집한다. 사이트는 종목 목록·일정 갱신용이며 사이트 변경만으로 알림을 만들지 않는다.
2. 목록에 있는 종목이 **새 글/새 영상 또는 기존 글·자막의 새 버전**에서 언급됐을 때 이벤트를 저장한다. 명시적 종목명/등록 별칭만 연결하고 부분 문자열 일치로 확정하지 않는다.
3. 새 이벤트만 AI로 한 줄 요약하고 참여/조건부/미참여/판단 불가를 근거와 함께 보존한다. 작성자가 청약하지 않겠다는 의견도 '새 언급'이므로 알림 대상이다. 요약은 원문에 없는 숫자·의견을 만들지 않는다.
4. 해당 이벤트의 한 줄 요약과 원문 링크만 Telegram으로 보낸다. **새 언급이 없으면 AI 분석도, 메시지 발송도 하지 않는다.** 같은 이벤트를 반복 전송하지 않는다.

첫 정상 실행은 기존 글/영상 전체를 기준선으로만 기록한다. 이미 있던 자료를 새 이벤트로 몰아서 보내지 않는다. 초기 기준선 이후 수집한 새 항목/변경만 이벤트로 취급한다. 새 종목이 목록에 추가됐다는 이유로 예전 글을 다시 알리지 않는다. 실패한 분석·전송은 저장된 이벤트 단위로 제한 재시도하므로 장애 때 발견 당일 전달을 보장할 수는 없다.

## 메시지 형태

```text
[종목명] 팽 블로그: 원문에서 새로 전달한 핵심 한 문장 (의견: 참여/조건부/미참여/판단 불가)
원문 링크
```

실제 문구는 원문과 모델의 검증된 응답을 사용한다. 위 문장은 형식 예시이지 실제 종목 분석 결과가 아니다.

## 명령과 상태

```bash
uv run ipo-monitor daily --allow-api       # 예약과 동일. 수집→감지→새 이벤트 분석→명시 활성 시 전달
uv run ipo-monitor daily --dry-run         # 수집·키·AI·전송 없이 대기 이벤트 미리보기
uv run ipo-monitor telegram catalog        # 확보한 월별 대상과 날짜 조회
uv run ipo-monitor telegram preview        # 아직 전송하지 않은 이벤트 요약만 미리보기
uv run ipo-monitor telegram send --allow-send  # 준비된 이벤트만 전달. 수집·AI 호출 없음
uv run ipo-monitor telegram disable
```

- `data/daily.sqlite3`: 원문 관찰과 현재 사이트 membership. 과거 자료 삭제 없음.
- `data/mention-events.sqlite3`: 월별 목록·최초 기준선·이벤트·AI 분석·발송 원장.
- `data/daily-ledger.sqlite3`: 일일 요청 상한600회, 입력당 재시도 최대3회,20시간 간격. 원격 응답 불명 요청도 한도에서 환급하지 않는다.20분 실행 예산 뒤 다음 실행으로 넘긴다.
- Telegram은 기존 로컬 연결을 재사용한다. 타임아웃/중단으로 수신 여부가 불명확한 이벤트는 unknown으로 보존하고 무조건 재발송하지 않는다. 알려진 전송 거절은 하루1회·최대3회만 재시도한다.
- 당일 성공한 사이트 목록이 없으면 발송하지 않는다. 청약 종료일 다음 날부터 제외한다. 목록이 부정확하면 멋대로 다른 종목으로 추정하지 않는다.

## 알려진 한계

- 유튜브 최신3개를 넘는 업로드는 놓칠 수 있다. 과거 영상 전체 검색 기능은 없다.
- 블로그 일일 공통 입력은 RSS이며 자동 본문 재확인은 이 이벤트 흐름에도 아직 연결하지 않았다. 짧은 원문에서 정보를 확정할 수 없으면 판단 불가로 남긴다.
- 수집 시각이 하루1회이므로 '그날 발송'은19시까지 확보한 자료 기준이다. 이후 게시물은 다음 실행에서 감지한다.
- 고정 응답/mock 테스트는 실제 AI 해석 정확도의 증거가 아니다. 새 이벤트용 요약 프롬프트는 따로 캐시 키를 사용한다.

## 검증·활성화 결과
